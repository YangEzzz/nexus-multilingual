# 前端企业级代码审查

日期：2026-10-12。范围：当前 `nexus-multilingual` 工作区，重点覆盖业务页面、请求层、认证、权限、共享表格、工程规范与交互契约。属于全项目现状审查，不是某个提交的增量审查。没有修改业务源码或执行自动格式化。

## 结论

项目有可复用的 shadcn-vue 基础组件、集中的权限定义和 Cookie 会话入口，但业务层存在数据一致性与异步生命周期缺陷，质量检查也未通过。当前不宜按企业级生产交付标准验收。

本报告列出 16 项发现：4 项 P1、10 项 P2、2 项 P3。P1 应优先修复；P2 应在对应业务或共享能力正式交付前处理；P3 属于规范和性能优化。优先级依据实际影响，而非文件长度或 lint 数量。

## 确认发现

### 1. [P1] 对象 JSON 导入执行用户粘贴的 JavaScript

位置：`src/views/Workbench/index.vue:1842–1847`。

`JSON.parse` 失败后，直接将输入拼入 `new Function` 执行。对象值、表达式、函数调用均可能在导入前执行；内容结构校验发生在执行之后，无法形成保护。具有导入权限的用户粘贴外部提供的片段时，可触发应用同源上下文中的任意 JavaScript。攻击代码能访问页面数据并以当前会话发起请求；HttpOnly Cookie 本身不必可读。

安全复现输入：`({value: (globalThis.__reviewMarker = 1, "text")})`。实际解析函数执行后标记变为 1。

建议：移除执行式解析，仅接受严格 JSON；如必须支持对象字面量，用非执行式解析器并限制允许的语法节点。拒绝调用、访问器及可执行表达式。

### 2. [P1] 抽屉翻译的晚到响应写入后来打开的词条

位置：`src/views/Workbench/index.vue:1683–1744`，尤其 1716–1719；`openDrawer:1503`、`closeDrawer:1752`。

请求前读取 A 的内容，await 后却重新访问共享的 `activeDrawerTerm.value`。用户等待时可关闭抽屉并打开 B，返回结果随后写入 B；关闭后未打开其他词条则会访问 null。当前没有词条、项目、请求版本校验。

隔离复现：A 请求挂起，切换 `activeDrawerTerm` 为 B，返回 A 的结果；输出为 `B / translation for A`。

建议：固定请求所属项目、词条 ID 和编辑版本；只在仍匹配时应用结果。抽屉切换或销毁时取消请求或使其失效，处理期间的保存行为也应保持一致。

### 3. [P1] 项目切换保留旧抽屉与编辑快照

位置：`src/views/Workbench/index.vue:458–468`、`547–550`、`1564–1573`、`2364`。

项目切换仅清理发布弹窗、页码和选择状态，没有清理 `activeDrawerTerm`、全局编辑模式、编辑快照、暂存翻译和相关弹窗。切换菜单可以直接更新项目 query。A 的抽屉仍打开时切到 B，保存 URL 使用 B 的项目 ID 和 A 的词条 ID；后端若正确校验归属会拒绝，但前端编辑上下文已经错误。全局编辑后切项目再点击放弃，还会把 A 的旧快照放回 B 的表格。

建议：统一项目上下文切换，先处理脏数据，再清理项目所属编辑与操作状态；所有 mutation 固定目标上下文，不从提交时的可变 route 重新推导。

### 4. [P1] 放弃编辑只回滚表格，没有回滚选中项缓存

位置：`src/views/Workbench/index.vue:547–550`、`861–870`、`880–882`、`508–530`。

选中缓存持有行对象引用。编辑会同时修改表格和缓存；放弃时用 JSON 反序列化替换 `terms`，缓存继续引用原来的已编辑对象。随后保存使用 `selectedTermsForBulk`，可再次提交用户已经放弃的修改。

内存模型复现输出：`rollback table: before / selected cache: edited`。

建议：以 ID 维护选择，使用统一实体状态；回滚同时恢复缓存并重新绑定引用，或让草稿完全独立于展示实体。验收场景必须覆盖“编辑→放弃→再编辑→保存”。

### 5. [P2] 批量翻译将失败统计为成功

位置：`src/views/Workbench/index.vue:810–814`、`1112–1120`。

`translateRow` 捕获 AI 错误后正常返回，甚至缺 Key、无参考内容、正在翻译时也直接返回。调用方 await 后无条件 `successCount++`，外层 catch 收不到这些失败。

用实际函数和模拟失败请求复现：先出现“AI 翻译失败”，再出现“批量翻译成功：已成功翻译 1 个词条”。

建议：返回明确的 success/failed/skipped 结果，让批量层统一汇总；busy 状态应在读取选中项之前设置，并在 finally 清理，防止解析选中项期间重复启动。

### 6. [P2] 校对失败后仍保留本地成功状态

位置：`src/views/Workbench/index.vue:1618–1629`、`1636–1638`、`1523–1526`。

先将抽屉状态改为 `review`，再提交。请求失败后不恢复原状态；校对按钮根据本地 status 隐藏，用户无法直接重试原操作，且界面状态与服务器不一致。

建议：在请求成功后提交本地状态；或保留旧值并在失败时回滚，显示可重试的行内错误。

### 7. [P2] 项目语言与提示词没有完整的请求竞态保护

位置：`src/views/Workbench/index.vue:307–335`、`426–438`、`442–456`；`src/views/Dashboard/index.vue:192–212`。

工作台词条列表已有请求序号保护，这是正确的局部设计；项目语言、提示词和仪表盘没有同等保护。A 的慢请求晚于 B 返回，会覆盖 B 的语言列、提示词或统计。此外，没有 ai_prompt 的项目不会将旧项目提示词恢复为默认值。

建议：统一按项目 ID 建立查询与失效策略；返回后验证上下文，或采用已有 Vue Query 依赖管理 queryKey、取消与缓存。切项目应显式初始化提示词和语言状态。

### 8. [P2] 项目语言 sessionStorage 缓存永久优先且没有失效

位置：`src/views/Projects/index.vue:125–128`、`200–204`；`src/views/Workbench/index.vue:312–318`。

进入工作台会写语言缓存，读取后直接 return，不再请求服务器。修改项目语言时没有失效这个缓存。用户从侧栏或已打开页面返回工作台可能继续使用旧语言，影响列展示、翻译目标和校对完整性校验。别的用户或页面改配置也无法感知。

建议：集中维护项目语言查询缓存；更新后失效，读取时重新验证或设置明确有效期。项目语言类型应包含 `is_source`，不要依赖 any 或语言代码猜测源语言。

### 9. [P2] 项目创建和语言保存是两个非原子操作，失败恢复不完整

位置：`src/views/Projects/index.vue:153–179`。

创建项目成功后才请求保存语言。第二个请求失败时显示整体失败，但项目已经存在，创建表单仍保持创建模式；重试会再次执行创建，可能产生重复记录或标识冲突。编辑同样可能只更新项目元数据，没有更新语言。

建议：优先使用服务端原子保存；否则记录已经创建的 ID 和部分成功结果，重试只完成剩余步骤。不能将已经成功的创建当作全部未执行。

### 10. [P2] 共享表格的服务端分页封装不完整

位置：`src/components/data-table/use-generate-vue-table.ts:22–40`、`69`、`79`。

`pageCount` 只在创建表格时取一次值，后续 total/pageSize 更新不反映到表格选项。服务端 pagination state 读取 props，但 `onPaginationChange` 只更新本地 ref，表格 API 翻页无法更新其实际读取的 state，也没有调用服务端回调。共享分页栏通过单独分支调用回调，掩盖了封装本身的问题。

目前 Tasks 使用客户端分页，因此这是服务端分页能力的潜在缺陷，不应描述为已确认的 Tasks 线上翻页故障。

建议：pageCount 使用响应式 getter；分页更新计算新值并交给服务端回调；为行选择提供稳定业务 ID，明确 manualSorting/manualFiltering 的责任。对 total 改变及 table.nextPage() 添加契约测试。

### 11. [P2] 请求层公开了与真实返回值不一致的方法

位置：`src/request/index.ts:103–106`、`142–153`、`162–168`。

blob 拦截器返回完整 AxiosResponse，但 `api.download` 声明 Promise<Blob>，调用者拿不到声明中的 Blob。stream 分支检查原生 Response，当前请求链没有将 Axios 返回值转换为原生 Response 的路径；如果沿用现有响应拦截器，无法得到约定的流。这些方法当前没有检索到业务调用，属于公开 API 契约缺陷。

建议：下载显式返回 response.data，流使用独立清晰的请求路径并验证 fetch adapter 的实际返回结构；删除未支持的能力比保留虚假的类型承诺更可靠。`use-axios.ts` 也没有业务调用，可移除或统一入口，避免以后绕过会话/CSRF策略。

### 12. [P2] 类型检查没有成为交付门禁，API 类型边界不足

位置：`package.json:8`；`src/views/Workbench/index.vue:50`、`277`、`601`、`790`、`1719`；`src/store/auth.ts:5`。

构建通过但 vue-tsc 失败；工作台 API items、项目详情和映射函数使用 any，认证 user 也是 any。业务对象的数据契约不足，项目类型还在 Dashboard、Projects 中分别维护，导致字段覆盖与状态演进难以可靠校验。

建议：增加 `typecheck` 脚本并串入 CI/发布检查；统一 Project、ProjectLanguage、TermDTO、TranslationDTO、SessionUser 类型。catch 使用 unknown 和统一错误解析函数；格式化不应通过关闭类型或安全规则来实现。

### 13. [P2] 抽屉和表格编辑缺少丢弃确认，存在静默数据丢失

位置：`src/views/Workbench/index.vue:1752–1755`、`625–641`、`3395`。

虽然计算了 `isDrawerDirty`，取消、Escape、遮罩关闭最终直接清空编辑对象。没有页面离开保护。全局编辑时搜索、过滤和分页仍可加载服务器行，覆盖本地改动；筛选变更同时清除选择，更难恢复。

建议：将取消、抽屉关闭、项目切换、路由离开统一交给脏数据保护；编辑期间冻结会替换实体的查询操作，或保留独立草稿并要求明确提交/放弃。

### 14. [P2] 导出语言选择不能完成正常键盘操作，抽屉宽度未适配窄屏

位置：`src/views/Workbench/index.vue:3803–3814`、`3396`。

语言条目由 div 的 click 驱动，既无键盘语义也无键盘事件；内部 Checkbox 只有 model-value，没有更新事件，键盘切换无法更新真正的 selectedExportLangs，也没有关联语言标签。抽屉覆盖基础组件宽度为固定 500px，窄于 500px 的视口会溢出。

建议：让 Checkbox 的更新事件直接驱动状态，并用关联 label 扩展点击区域；避免嵌套交互控件。抽屉使用 `w-full sm:max-w-[500px]` 等可收缩约束。需要浏览器键盘和 375px 视口验证。

### 15. [P3] 格式规范已配置，但缺少执行一致性

位置：`eslint.config.mjs:24–45`；`src/views/Dashboard/index.vue`、`src/views/Workbench/index.vue`。

327 条 warnings 中，169 条是 func-style，142 条是单行模板换行，合计 311 条。大量风格警告会淹没真实问题。59 个 errors 还包含文档表格格式、import 顺序、换行和 no-use-before-define；后者必须区分延迟执行闭包和真实初始化顺序，不能一律宣称运行时错误。

建议：团队统一函数声明或箭头函数约定，让配置和代码一致；将一次性的格式清理独立提交，避免和行为修复混合。ESLint 已通过 antfu 集成 formatter，不必再引入冲突的格式工具。自有修改过的 ui 组件应至少保留类型与关键检查，不应永久全目录绕过。

### 16. [P3] 工作台组件职责过宽，重复逻辑已导致业务分歧与大包

位置：`src/views/Workbench/index.vue`（4,001 行）；翻译入口 743、1683 行，更新负载 520、829、940、1566、1623 行；静态 XLSX 导入 7 行。

工作台同时负责项目上下文、请求、选择缓存、状态流转、编辑草稿、翻译、导入、导出和十余个弹窗。行翻译复用 globalPrompt 并直接设 review，抽屉翻译使用独立固定提示词且对 draft 设 pending；相同动作具有不同策略。请求更新负载重复，容易出现字段与权限漂移。XLSX 在访问工作台时就被加载，而非导入时加载；当前 Workbench 包 455.03 kB，但不能把全部体积都归因于 XLSX。

建议：先消除重复策略，再拆分组件。将 DTO 映射、提示词构建、状态转换和 import 解析抽为纯函数；将草稿、选择和请求生命周期分别封装为 composable；把 XLSX 改为功能触发时动态导入。组件大小是维护信号，不是单独的功能缺陷。

## 推荐封装与组件边界

| 层                                      | 推荐职责                                       | 约束                                            |
| --------------------------------------- | ---------------------------------------------- | ----------------------------------------------- |
| API / DTO                               | project、term、language API 与明确类型         | 不负责 toast、路由、弹窗                        |
| 领域纯函数                              | 映射、校验、占位符、提示词、状态转换、导入解析 | 不依赖 Vue 和可变 route，方便验证               |
| `useProjectContext`                     | 项目 ID、语言、详情、上下文切换和失效          | 统一处理旧请求和项目状态                        |
| `useTermQuery`                          | 筛选、分页、请求、错误和刷新                   | 保留现有防过期响应能力，统一查询 key            |
| `useTermSelection`                      | 显式选择、跨页全选、排除范围                   | 以 ID 为主，不另造失控实体副本                  |
| `useTermDraft`                          | 编辑原值、草稿、dirty、提交和放弃              | 所有入口共享一个提交/回滚语义                   |
| `useTermTranslation`                    | 单行/抽屉/批量翻译策略与结果                   | 明确返回 success/failed/skipped，固定请求上下文 |
| `WorkbenchToolbar` / `TermFilterBar`    | 操作入口与筛选展示                             | 通过 props/emits，不隐藏数据请求                |
| `TermTable` / `TermEditorSheet`         | 数据展示、行编辑和抽屉表单                     | 共享字段规则和权限，表格可保留领域特化          |
| Import / Export / Bulk / Release Dialog | 各自完整的业务交互                             | 复用 shadcn-vue 弹窗，不复制底层可访问性实现    |

抽取应以职责、重复策略、生命周期和可测试性为依据，不要机械地把每个小块都变成组件，也不要强迫多语言比较表套进现有 Tasks 通用表格。共享基础组件与领域组件各有合理边界。

## 其他观察与验证候选

- 权限定义集中、未知权限拒绝、操作函数再次校验、SSO 消息校验 origin/source/transaction、退出先撤销服务端会话，属于值得保留的设计。
- Tasks 路由仍是静态 JSON 示例，删除和保存只显示 toast，没有持久化。若属于保留的开发演示，应明确隔离；若承诺生产业务，则需接入真实 CRUD。当前没有足够产品依据将它定为生产功能缺陷。
- 单行删除只移除本地行，未刷新 total、status counts、summary 和选择缓存，界面计数会暂时失真；建议纳入 mutation 后统一失效策略。
- 筛选、分页没有恢复到 URL，用户刷新/返回会失去列表上下文。需要根据产品约定决定持久化边界。
- 日期格式、错误消息解析、项目类型和语言加载存在跨页面重复，适合集中到小型明确工具，不建议抽一个承担所有 CRUD 的巨型通用 composable。
- 静态审计把 `<Select>` 和 `as-child` 触发器部分误判为原生 select 或无行为按钮。这些候选需要读组件与事件链确认；不能照单全收。
- 已有权限浏览器测试，但 package scripts 没有 test/typecheck 命令，未发现已提交的 CI 流程。需要将已有测试接入自动执行，补上异步、回滚和失败恢复场景。

## 修复顺序与验收

1. 先修 P1：非执行式导入解析、翻译上下文隔离、项目切换保护、缓存回滚。
2. 修正批量结果、校对失败回滚、查询竞态、语言缓存失效、项目部分成功恢复。
